## What To Build

### Option A: Middleware Approach (Recommended)

Create a `middleware.js` at the app root that applies rate limits based on route patterns:

```javascript
// middleware.js (app root)
import { applyRateLimit, getClientIp } from '@/lib/rate-limit';

const ROUTE_LIMITS = {
  '/api/super-admin/auth': { maxRequests: 5, windowMs: 60_000, keyPrefix: 'auth' },
  '/api/purchase': { maxRequests: 10, windowMs: 60_000, keyPrefix: 'purchase' },
  '/api/webhook': { maxRequests: 60, windowMs: 60_000, keyPrefix: 'webhook' },
  '/api/mikrotik': { maxRequests: 20, windowMs: 60_000, keyPrefix: 'mikrotik' },
  '/api': { maxRequests: 30, windowMs: 60_000, keyPrefix: 'api' }, // default
};
```

### Option B: Per-Route Integration

Add rate limit check at the top of each route handler:

```javascript
import { rateLimitStrict } from '@/lib/rate-limit';

export async function POST(request) {
  const rateLimited = rateLimitStrict(request);
  if (rateLimited) return rateLimited;
  // ... rest of handler
}
```

## Upgrade Path

> Current implementation uses **in-memory store** (per Vercel instance). This means:
> - Rate limits reset on cold starts
> - Different instances have independent counters
> 
> For production at scale, upgrade to **Upstash Redis** for distributed rate limiting.
