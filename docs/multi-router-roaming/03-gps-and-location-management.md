# 03. GPS & Location Management

> **Geographic Intelligence**: Google Maps / Mapbox integration, GPS radius geofencing, and multi-signal location resolution.

---

## 1. Location Data Model & Geofencing

Every physical hotspot location represents a point coordinate $(lat, lng)$ with a circular coverage radius $R$ in meters.

### The Haversine Proximity Formula
When the user's browser provides GPS coordinates $(\phi_u, \lambda_u)$, distance to location $(\phi_l, \lambda_l)$ is calculated using the spherical law of cosines:

$$d = 2R_e \cdot \arcsin\left(\sqrt{\sin^2\left(\frac{\Delta\phi}{2}\right) + \cos\phi_u \cos\phi_l \sin^2\left(\frac{\Delta\lambda}{2}\right)}\right)$$

Where $R_e \approx 6,371,000 \text{ m}$ (Earth radius).

If $d \le R_{\text{coverage}}$, the user is inside the hotspot geofence.

## 2. Multi-Signal Location Resolution Strategy

A major technical trap in captive portal development is relying **exclusively** on GPS.
- Inside buildings, GPS signal can be weak or drift by 50+ meters.
- Laptop browsers often lack hardware GPS chips.
- Mobile CNA (Captive Network Assistant) sheets frequently block HTML5 Geolocation API requests.

Asuk Tech uses a **3-Tier Multi-Signal Resolution Engine**:

```
                              ┌───────────────────────────────────┐
                              │     User Joins Wi-Fi Network      │
                              └─────────────────┬─────────────────┘
                                                │
                                                ▼
                             [Signal 1: Captive Portal URL Param]
                                  ?router=$(identity)&ip=$(ip)
                                                │
                                    ┌───────────┴───────────┐
                                   Found?                  Not Found
                                    │                       │
                                    ▼                       ▼
                         [100% Deterministic]     [Signal 2: HTML5 Geolocation]
                         Matched to Router by     navigator.geolocation (GPS)
                         Unique Hardware Identity           │
                                                ┌───────────┴───────────┐
                                             Granted?                Denied
                                                │                       │
                                                ▼                       ▼
                                      [Haversine Match]     [Signal 3: Subnet Match]
                                      Within Radius of      Client IP matched to
                                      Location GPS Pin      Router DHCP Subnet Range
```

### Signal 1: Hardware Identity (Primary & Authoritative)
The captive portal template generated by Asuk Tech embeds the router's identity directly into the redirect URL:
```html
<a href="https://asuktech.net/packages?router=$(identity)&mac=$(mac)&ip=$(ip)&server=$(server-name)">
```
When the user arrives at `/packages`, the platform extracts `?router=Asuk-R1-HQ`, immediately resolving the location with **zero user permissions required**.

### Signal 2: GPS Browser Geolocation (Proximity & Map Discovery)
- The mobile/web application requests `navigator.geolocation.getCurrentPosition()`.
- Plots the user on an interactive map showing all nearby hotspot branches.
- Validates that the user is physically within the coverage radius of the router they are connecting through.

### Signal 3: Subnet Matching (Network Layer Fallback)
- Each router has an assigned local DHCP IP pool (e.g., `192.168.88.0/24` for Location A, `192.168.89.0/24` for Location B).
- If client IP is reported, the backend can map the subnet to the corresponding router.

## 3. Administrator Location Manager UI

Administrators configure locations via the Super Admin **Locations & Routers** tab:

### 1. Map Widget (Google Maps API / Mapbox GL JS)
- **Search Autocomplete**: Admin types an address (e.g. "Ikeja City Mall, Lagos") and Google Places / Mapbox Geocoding autocompletes and centers the map.
- **Draggable Pin**: Admin fine-tunes the exact rooftop or access point placement.
- **Dynamic Radius Circle**: Slider allows adjusting coverage radius (50m, 100m, 250m, 500m) rendered in real-time as a semi-transparent colored circle.

### 2. Device Association
- Admin selects which MikroTik router hardware serves this location.
- Generates the customized RouterOS configuration script with pre-filled `identity`, `hotspot_server_name`, and polling credentials.
